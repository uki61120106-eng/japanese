# パズルRPG「ドロップクエスト」要件定義書

個人で遊ぶことを目的とした、落ち物パズル × RPG のアプリ。v0（初回リリース）の要件。
同じリポジトリの学習アプリ「かなフラッシュ」とは独立した画面として `/puzzle` に追加する。

## 1. 目的とスコープ

| 項目 | 内容 |
| --- | --- |
| 何のアプリか | ドロップを揃えて敵を倒す、パズル操作のロールプレイングゲーム |
| 想定ユーザー | 作者本人。個人で遊ぶ。公開・配布・課金はしない |
| 今回の位置づけ | v0。通信なし・ログインなしでブラウザ単体で動く |
| 学習要素 | 持たない（かな学習とは混ぜない） |

### 今回作るもの

- 盤面のドロップ操作、コンボ判定、落下・補充・連鎖
- 敵とのターン制バトル、属性相性、リーダースキル
- モンスターの収集・レベルアップ・合成強化、パーティ編成
- 複数のダンジョンと進行状況の保存

### 今回は作らないもの（次段階の検討事項）

- アクティブスキル（ドロップ変換・敵の行動遅延など）
- 進化合成、覚醒スキル、潜在覚醒
- スタミナ、ガチャ、協力プレイ、ランキング
- 効果音・BGM、キャラクターの描画（絵文字で代用する）

## 2. ゲームの仕組み

### 2.1 盤面

| 項目 | 決定内容 |
| --- | --- |
| 盤面サイズ | 横6 × 縦5（30マス） |
| ドロップの種類 | 火・水・木・光・闇・回復 の6種 |
| 操作 | ドロップを掴んで動かし、通過したドロップと入れ替える |
| 操作時間 | 既定8秒。ホーム画面で 5 / 8 / 12 秒・無制限 から選べる |
| 消える条件 | 縦または横に同じ色が3つ以上並ぶ |
| コンボの数え方 | 3つ以上並んだマスのうち、同色で隣接するものを1コンボとして数える（L字・十字は1コンボ） |
| 連鎖 | 消えた後に上から落ちて補充され、再び揃えばコンボが加算される |

### 2.2 ダメージ計算

事実として、本作は以下の式で固定する（実装 `src/lib/puzzle/battle.ts`）。

```
1コンボあたりの個数倍率 = 1 + 0.25 × (消した個数 - 3)
コンボ倍率             = 1 + 0.25 × (総コンボ数 - 1)
与ダメージ = 攻撃力 × 個数倍率 × コンボ倍率 × リーダー補正 × 属性相性
回復量     = 回復力合計 × 個数倍率 × コンボ倍率 × リーダー補正
```

- 攻撃するのは、消したドロップと同じ属性のモンスターだけ
- 回復ドロップは攻撃せず、HP を回復する
- 属性相性：火→木、木→水、水→火 が2倍（逆は0.5倍）。光⇔闇 は相互に2倍。等倍はそれ以外

### 2.3 バトルの進行

1. フロア開始。敵が1〜3体出現する
2. プレイヤーがドロップを操作 → コンボ確定 → 味方が攻撃 → 回復
3. 倒しきれなかった敵の攻撃カウントが1減り、0になった敵が攻撃してくる
4. HP が0になったら敗北（ホームへ戻る。報酬なし）
5. 敵を全滅させたら次のフロアへ。盤面はそのまま引き継ぐ
6. 最終フロアを突破したらクリア。経験値とモンスターのドロップを受け取る

攻撃対象は敵をタップして選べる。既定は左端の生存している敵。

### 2.4 パーティとモンスター

| 項目 | 決定内容 |
| --- | --- |
| 編成 | 4体。先頭がリーダーで、そのリーダースキルだけが効く |
| ステータス | HP・攻撃力・回復力の3つ。Lv1 と 最大Lv の値を線形補間する |
| 属性 | 火・水・木・光・闇 のいずれか1つ |
| 収録数 | 15種（各属性3種、レア度1〜3） |
| 入手 | ダンジョンのクリア報酬として確率で入手 |

### 2.5 育成

| 項目 | 決定内容 |
| --- | --- |
| 経験値 | ダンジョンクリア時にパーティ全員へ配分 |
| 必要経験値 | `40 × Lv^1.9`（切り上げ） |
| 合成 | 手持ちのモンスターを素材にして経験値を与える。素材は消滅する |
| 素材の経験値 | `レア度 × 300 + 現在Lv × 100`。同属性なら1.5倍 |
| 制限 | パーティ編成中のモンスターは素材にできない |

## 3. 画面

`/puzzle` の1ルートの中で、次の画面を切り替える。

### 3.1 ホーム
- パーティ4体の表示（HP・攻撃力・回復力の合計とリーダースキル）
- ダンジョンの一覧（クリア済みの表示、前提ダンジョン未クリアなら選択不可）
- 「編成」「モンスター」「操作時間」の設定
- かなフラッシュへ戻るリンク

### 3.2 バトル
- 上部：敵（属性・HP バー・攻撃までの残りターン）
- 中部：パーティの HP バーとターン数、直近のコンボ表示
- 下部：6×5 の盤面（ドラッグで操作、時間制限のゲージ）

### 3.3 リザルト
- 勝敗、獲得経験値、レベルアップしたモンスター、入手したモンスター
- 「もう一度」「ホームへ」

### 3.4 モンスター / 編成
- 手持ち一覧（属性・Lv・ステータス）
- パーティ枠への出し入れ、リーダーの入れ替え
- 合成強化（素材を複数選んで実行、獲得経験値の事前表示）

## 4. デザイン方針

- かなフラッシュと同じ Tailwind のトークン・角丸・フォントを使い、同じアプリの別画面に見えるようにする
- 属性ごとに色を割り当て、ドロップ・モンスター・敵で色を共有する
- スマートフォン幅（〜420px）を基準にする。盤面は画面幅にあわせて伸縮する
- OS のダークモード設定に追従する

## 5. 技術要件

| 項目 | 内容 |
| --- | --- |
| フレームワーク | Next.js（App Router）+ TypeScript。`/puzzle` はクライアントコンポーネント |
| UI | shadcn/ui + Tailwind CSS v4 |
| 通信 | なし。モンスター・ダンジョンのデータはアプリに同梱する |
| 保存 | localStorage（キー `dropquest.save.v1`）。手持ち・編成・クリア状況・設定を保存する |
| ポインタ操作 | Pointer Events でマウス・タッチを共通に扱う |
| テスト | 盤面判定とダメージ計算を `node --test` で検証する（`npm test`） |

## 6. バランスの確認（実装後の記録）

事実として、ブラウザを自動操作して次を確認した。推論として、実際に人が操作すればこれより少ない手数で済むと考えられる。

| 確認したこと | 結果 |
| --- | --- |
| 初期パーティ（Lv1 × 4体）で「はじまりの草原」をクリアできるか | 14ターンでクリア。全員 Lv1 → Lv5 |
| ドロップを掴んで動かさずに離したとき | ターンを消費しない |
| 属性相性が与ダメージに反映されるか | 内訳表示（例：水 690 ↓）で不利を確認 |

初回でクリアできないと経験値が入らず詰むため、最初のダンジョンは初期パーティで突破できる強さに合わせている。

## 7. リスクと対応（作る前の整理）

| 懸念 | 対応 |
| --- | --- |
| localStorage はブラウザや端末を変えると消える | v0 は許容。バックアップが要るならエクスポート機能を次段階で検討 |
| 盤面操作の判定がスマホで重い / 誤爆する | 1マスの中心に入った時点で入れ替える方式にし、`touch-action: none` でスクロールを止める |
| バランス調整が青天井になる | 数値は `monsters.ts` / `dungeons.ts` に集約し、ロジックから切り離す |
| 商標 | 既存作品の名称・キャラクター名は使わない。名称はすべて独自のものにする |
