# えいかいわフラッシュ 要件定義書

デモ版（v0）の要件。ヒアリング（一問一答）の結果をそのまま記録したもの。

## 1. 目的とスコープ

| 項目 | 内容 |
| --- | --- |
| 何のアプリか | 日本語話者が英会話の決まり文句を覚えるための学習アプリ |
| 想定ユーザー | 英語の初心者（中学1〜2年程度の語彙・文型で足りる人） |
| 今回の位置づけ | デモアプリ。ログインなし・保存なしで単体で動くこと |
| 既存アプリとの関係 | 同じリポジトリに別アプリとして追加。トップページから2つを選ぶ |

## 2. 学習の仕組み

| 項目 | 決定内容 |
| --- | --- |
| 練習の形 | フラッシュカード（表: 日本語 → タップ → 裏: 英語） |
| カードの表 | 日本語の意味（例: `こんにちは。`）と場面名 |
| カードの裏 | 英語（`Hello.`）＋ カタカナ読み ＋ 使い方のひとこと ＋ 相手の返事の例 |
| 収録範囲 | 7場面 × 8フレーズ ＝ 56フレーズ |
| 出題範囲の指定 | 場面を複数選択（2グループに分けて表示） |
| 出題順 | シャッフル ON / OFF を切り替え可能 |
| 練習モード | 「聞いて覚える」／「声に出す」の2つ |
| 読み上げ | 標準の速さと、ゆっくり（0.6倍）の2ボタン |
| 発音チェック | 「声に出す」モードのみ。マイクで聞き取り、お手本と照合する |
| 1枚ごとの操作 | 「まだ むずかしい」「言えた」の2ボタンで次のカードへ |
| セット終了時 | 結果画面（正答率・件数・言えなかったフレーズの一覧） |
| 復習 | 「むずかしい N フレーズをもう一回」「おなじ N フレーズをもう一回」 |

### 2.1 収録する場面

| グループ | 場面 | 内容 |
| --- | --- | --- |
| あいさつ・自己紹介 | あいさつ | 朝・昼・夜のあいさつ |
| あいさつ・自己紹介 | 自己紹介 | 名前・出身・仕事 |
| あいさつ・自己紹介 | お礼とおわび | 感謝とおわび |
| 旅行・買い物・レストラン | 空港と移動 | チケットと乗り物 |
| 旅行・買い物・レストラン | 買い物 | 値段をきいて買う |
| 旅行・買い物・レストラン | レストラン | 注文からお会計まで |
| 旅行・買い物・レストラン | 道をたずねる | 場所と行き方をきく |

### 2.2 発音チェックの判定

**発音の良し悪しではなく「意図した文を言えたか」を見る。** 音声認識が返した文字列と
お手本を、語順を保ったまま単語単位で突き合わせる（最長共通部分列）。

| 項目 | 決定内容 |
| --- | --- |
| 比較の前処理 | 小文字化、記号とアポストロフィの除去 |
| 表記ゆれの吸収 | 数字はつづりへ（`2` → `two`）、短縮形は一方へそろえる（`I am` → `I'm`） |
| 点数 | 一致した語数 ÷ （お手本と聞き取りの長いほう）× 100 |
| 判定 | 100点 = そのとおり！／60点以上 = おしい！／60点未満 = もう一度 |
| 画面表示 | 言えていない語に波線を引き、聞き取られた文もそのまま出す |

分母に「長いほう」を使うのは、余計な語をたくさん言っても満点にならないようにするため。

## 3. 画面

### 3.0 トップ（アプリの選択）
- かなフラッシュ / えいかいわフラッシュ の2枚のカード
- 各アプリから「アプリをえらぶ」でここへ戻る

### 3.1 ホーム
- 練習モードの切替タブ（聞いて覚える / 声に出す）
- 場面の選択（複数選択、「すべて選ぶ / すべて外す」）
- シャッフルの ON / OFF
- 選択フレーズ数の表示、スタートボタン
- 場面が0個のときはスタートを無効化

### 3.2 練習
- 進捗表示（`3 / 24 フレーズ`）とプログレスバー
- カード（タップで表裏がめくれる。3Dフリップ）
- 「聞く」「ゆっくり」の読み上げボタン
- 「声に出す」モードでは発音チェック（マイクボタンと判定結果）
- 「まだ むずかしい」「言えた」ボタン
- 「やめる」でホームへ戻る

### 3.3 結果
- 正答率（%）、言えた件数 / まだむずかしい件数
- 言えなかったフレーズの一覧（英語と日本語）
- 「むずかしい N フレーズをもう一回」「おなじ N フレーズをもう一回」「ホームへもどる」

## 4. デザイン方針

かなフラッシュと同じ考え方をそろえる。

- ポップでカラフル。場面ごとに色を割り当て、カード表面・場面チップ・進捗バーで色を共有する
- 角丸を大きめに取り、丸ゴシック（M PLUS Rounded 1c）で親しみやすい印象にする
- スマートフォン幅（〜420px）を基準にレイアウトする。320px でも横スクロールしない
- OS のダークモード設定に追従する（切替 UI は持たない）
- アプリごとに背景のグラデーションを変える（かな = 暖色、えいかいわ = 寒色）

## 5. 技術要件

| 項目 | 内容 |
| --- | --- |
| フレームワーク | Next.js 16（App Router）+ TypeScript |
| UI | shadcn/ui + Tailwind CSS v4 |
| ルーティング | `/` トップ、`/kana` かなフラッシュ、`/english` えいかいわフラッシュ |
| 読み上げ | ブラウザ内蔵の SpeechSynthesis（`en-US`）。サーバーも API キーも使わない |
| 聞き取り | ブラウザ内蔵の SpeechRecognition（`en-US`）。サーバーも API キーも使わない |
| フレーズのデータ | アプリに同梱する（`src/lib/phrases.ts`） |
| 状態 | React の state のみ。保存・永続化はしない |
| 対応 | 最新のモダンブラウザ（スマホ幅を優先） |

## 6. 制約と留意点

導入を判断するうえで、先に把握しておくべき事項。

### 6.1 音声機能はブラウザ依存

| 機能 | 対応状況 |
| --- | --- |
| 読み上げ（SpeechSynthesis） | ほぼすべてのモダンブラウザで使える |
| 聞き取り（SpeechRecognition） | Chrome / Edge / Safari 系は対応。**Firefox は未対応** |

聞き取りに対応しない環境では「声に出す」タブを選べないようにし、理由を画面に出す。
読み上げに対応しない環境では、カタカナ読みを頼りにする旨を出す。

### 6.2 音声データの扱い

**事実**: W3C の Web Speech API 仕様は、認識処理をブラウザ内で行うか外部サービスで行うかを
実装に委ねている。Chrome の実装は音声データをブラウザベンダーのサーバーへ送って認識する。

**このアプリの位置づけ**: アプリ自身はサーバーを持たず、フレーズのデータも同梱しているため、
**このアプリが外部へ送信するものは無い**。ただし「声に出す」モードを使うと、
ブラウザが音声をベンダーへ送る可能性がある。したがって、かなフラッシュのように
「通信は一切ない」とは言い切れない。

**運用上の前提**: 読み上げるのは同梱の定型フレーズのみで、個人情報を話させる設計にはしない。
業務利用に広げる場合は、この点の確認を別途行うこと。

### 6.3 判定精度

音声認識の結果は、周囲の雑音・マイク品質・話者の訛りに左右される。
正しく言えていても低い点が出ることはあるため、点数は目安として扱い、
先に進むかどうかは学習者の「言えた / まだ むずかしい」の自己申告で決める設計にしている。

将来の検討事項として記録しておく。

- ログイン、サーバー保存、学習履歴の永続化

- 発音そのものの採点（母音・子音の当たり判定）
